# レビューから還元した判断



- 独立checkoutで配る正本は `sites/business-sovereignty/materials/business.json` と `materials/methodology.md`。初期構想と実装済み条件を混同せず、存在しない兄弟ディレクトリへ手順を向けない。
- 二言語の契約にはコードポイント、日時の字句と暦日、整数と真偽値の区別を含め、同じ反例と双方向移行を実行する。JSON数値1.0は値として整数であるため受理し、非整数値を拒否する。
- ハッシュは同一性の証拠に限る。仕様の定数を両実装が実際に読み、変更反映と未対応仕様の起動拒否を行動で検査する。
- 通常のテナント操作とworkspace管理の例外を仕様に明記する。仕様切替も操作者・時刻・前後版を監査する。学習保存は業務revisionから分離する。
- 件数だけでなく要求・保存・履歴の容量上限を契約に含める。最大長のUnicode入力で上限件数まで保存・再読出し・移行する。IPCバッファを広げるだけで修正済みとしない。
- 証拠画面は静的記録であること、対象commit・入力ハッシュ・種別・子結果・未実施を示す。古い公開確認を現行コードのPASSへ読み替えない。
- ローカル取込はGit管理のメディアを上書きしない。共有用スナップショットは認証IDを教材用に置換する。過去履歴の残存を明記し、履歴の強制書換は別途判断する。
